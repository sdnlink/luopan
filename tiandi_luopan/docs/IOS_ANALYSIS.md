# iOS 工程分析与实现说明

## 运行链路

- `SceneDelegate` 创建 `ViewController`，`ViewController` 承载 `RootContentView`；根视图包含罗盘、AR、户型、玄空分析和设置五个 Tab。
- `CompassMotionManager` 汇总 Core Location 航向/定位和 Core Motion 姿态/磁场数据，经过环形角度滤波后发布给 SwiftUI。罗盘盘面只旋转磁北盘，真北针单独叠加偏角。
- 各分析引擎（奇门、飞星、八宅、三合、天机等）是本地 Swift 计算，AR 使用 `AVCaptureSession`，截图由 UIKit 绘制水印。
- 会员流程由 `StoreKitIAPManager` 监听 StoreKit 1 交易队列，UI 通过 `VIPPaywallSheet` 和设置页购买/恢复权益。

## 已发现的主要问题

1. iOS 只读取 `CLHeading.trueHeading`，没有和 Android/小程序一致的 WMM 离线模型；没有定位或系统缓存失效时偏角会回到 0°。
2. AR 页面原先只有按方位映射形煞的规则，没有图像分析；“AI 扫描”在 Web 版本是固定延时和固定结果，不能作为真实识别。
3. StoreKit 商品未返回时购买按钮没有稳定的失败状态；购买错误没有统一传给 SwiftUI，年度会员过期后仅在初始化时刷新；价格显示硬编码。
4. Web 收银台在没有原生桥时会写入本地“购买成功”状态，存在伪造权益的风险；数字内容应该只走 App Store In-App Purchase，不能把 Apple Pay 当成替代渠道。
5. AR 截图使用 `UIImageWriteToSavedPhotosAlbum`，不检查 Photos 权限和保存结果；相机会在页面生命周期切换时频繁重建，权限拒绝时只能显示仿真画板。

## 本次实现

- 新增 `Models/WorldMagneticModel.swift`：移植 WMM 2020-2025 13 阶系数和椭球坐标、Schmidt 准正规化、时间漂移解算，输出北/东/下分量、偏角、倾角和总场强。定位回调现在用同一份 WMM 结果驱动真北针，并保留 Core Location 真北作为首次定位前的兜底。
- 新增 `Models/OnDeviceShaAnalyzer.swift`：使用 Vision `VNDetectRectanglesRequest` 在设备端分析当前相机帧，按几何区域、长宽比和位置给出形煞候选、置信度和目标点；不上传图像、不需要网络或模型密钥。AR 页面新增扫描按钮并将结果映射到目标框。
- StoreKit 管理器增加商品加载、购买中、错误、完成状态，年度权益按已有到期时间顺延，前后台切换时重新计算过期权益；会员页面显示 App Store 本地化价格并呈现失败提示。
- Web 收银台移除无原生环境下的模拟购买成功逻辑，改为提示用户在原生 App 内通过 App Store 完成购买；页面文案统一为 StoreKit/App Store 内购。
- 截图改为 `PHPhotoLibrary` 授权后保存，并显示保存失败信息；工程链接 Vision 和 Photos framework。
- 完成全页面国际化审计：`LocalizationManager` 的简体、繁体、英文三套字典均为 370 个唯一 key，修复重复/缺失 key，并覆盖罗盘、户型、AR、奇门、八宅、分金和设置页的动态结果。
- 户型诊断、AR 形煞危害/古籍/化解、八路黄泉口诀、奇门九宫字段、节气、天机长卷标题与报告正文均根据当前语言输出；罗盘模型字段增加英文/繁体显示属性，避免页面直接渲染中文原始数据。
- 户型单次商品现在在首次导入户型图或打开房间详勘时实际扣减一次，同一页面会话内复用已取得的访问权；切换语言会刷新示例文案并保留用户拖拽后的房间位置。
- 户型图导入改为选图成功后才扣减额度，取消系统相册选择不会消耗权益；仅持有未使用额度时不会提前解锁整页示例详勘。
- 天机长卷和 AR 存图均通过 Photos `addOnly` 授权并检查 `performChanges` 结果，保存失败不会扣减天机权益，也会在页面显示失败提示。
- 天机长卷的系统分享改为在 `UIActivityViewController` 完成分享后才扣减单次权益，用户取消分享不会被扣费。
- Android/iOS Web 长卷预览也改为在实际保存/下载时扣减天机单次额度，单纯生成预览或 Android 相册保存失败不会消耗额度。
- Android/iOS Web 户型页补齐单次额度门控：首次进入户型页扣减一次并在当前会话复用，未购买时会回到会员中心，不再无限免费使用完整诊断。
- Web 端传感器、支付、导出、AI 扫描和户型同步提示改用当前语言显示；两套 Web 资源均通过 Node 脚本语法检查。
- Android WebView 的外部钱包调用只进入“待验证”状态，不再凭调起支付 App 就发放权益；文件跨域、混合内容、地理位置和相机资源权限均已收紧。
- Android 图片保存兼容 Android 9 及以下的存储权限，检查 JPEG 压缩和 MediaStore 插入结果，失败时清理残留 URI。
- Android Gradle release 签名改为显式环境变量/Gradle 属性注入；仓库不再包含硬编码签名密码，缺少私钥时可生成未签名 release 用于 CI 静态构建。Linux 下的 Gradle Wrapper 已补齐可执行权限。
- 新增 `setup_and_build.sh`，在 Linux/macOS 上检查 JDK、Android SDK、Command-line Tools 与 API 34，并统一调用 Gradle 构建；当前容器只有 JRE 且网络受限，无法下载 JDK/Gradle/Maven 依赖。
- 修复繁体中文下奇门八门文案、奇门导航摘要和玄空飞星评价仍显示简体中文的问题；跨平台 Swift 审计脚本现在按仓库相对路径工作，可在 Linux/macOS/Windows 执行。
- 继续修复 iOS 功能边界：AR 前后摄像头切换会重建 `AVCaptureSession`，无对应镜头时回退并提示；形煞目标拖动改为累加位移，罗盘拨盘手势支持跨 0° 连续旋转。
- 移除首次定位前的北京示例坐标，定位权限拒绝时明确显示“尚未获取定位”；定位成功后保持低频位置更新，使实时坐标和速度不会在第一次定位后冻结。
- 未取得有效经度时不再展示占位经度计算的真太阳时，权限拒绝或定位失败会显示定位不可用。
- 修复年度订阅恢复重复叠加 365 天的问题；恢复交易不再当作新订阅顺延，购买/恢复操作也增加并发保护。
- iPad 天机长卷分享补充 `UIActivityViewController` popover 锚点，避免分享面板因缺少来源视图而崩溃。
- 相机会话增加中断结束、运行时错误和媒体服务重置恢复；拍照请求增加并发保护，并将会话启停串行化，避免来电/切后台后预览黑屏或回调错配。
- 户型图导入会将超大原图降采样到最长边 4096 像素，降低相册原图在 SwiftUI 画布中长期占用的内存峰值。
- 相机权限被拒绝时显示明确提示并提供跳转系统设置按钮，不再把权限关闭误显示为普通模拟器模式。
- 择日月柱改按太阳节气月界计算；玄空元运和年柱在二月改用天文立春节气桶判断，避免公历月份导致立春前后排盘错误。
- AR 存证只接受真实相机帧，权限拒绝或拍摄失败不会再生成深色占位图；Vision 分析同时保留照片方向，避免横竖屏帧被错误解读。
- 定价展示不再按语言写死人民币、新台币或美元；VIP 卡片、设置页、收银台和天机导出入口统一读取 StoreKit 的 `priceLocale`。商品尚未加载或不可用时显示加载/不可用状态，避免把错误地区价格当作实际价格。
- 奇门阴遁/阳遁、紫白流年与流月切换改用太阳黄经节气桶；奇门“最佳动身方”改为按开门优先、生门次之选出，不再被九宫遍历顺序覆盖。
- 天机长卷落款的岁次干支也改用同一节气判断，避免长卷与择日、玄空页面在立春临界日显示不同年份。
- 罗盘图层开关和流派预设现在持久化到 `UserDefaults`，重启 App 后保留用户的显示偏好。
- 真太阳时在夏令时地区改用时区标准偏移经线，避免把夏令时额外的一小时误算成 15° 经度误差。
- StoreKit 商品、交易和恢复回调统一回到主线程处理；交易 ID 以原子方式认领，避免重复回调重复发放权益；恢复流程忽略意外重放的消耗型商品。
- 户型与天机额度扣减使用串行锁保护，连续点击或并发回调不会重复消耗同一份额度。
- 天机长卷保存和系统分享增加导出中状态，成功保存/完成分享后才扣减额度，失败或取消不会重复触发导出。
- 分金角度查询增加安全兜底，数据表异常时不会因强制解包导致罗盘崩溃。
- 择日与玄空元运的公历日历统一绑定当前时区，避免 GMT 与本地日期跨日时出现年、月、日柱或元运错一天的问题。
- 设置页在定位被拒绝时提供系统设置入口，在尚未决定时提供重新请求权限入口，避免用户无法恢复真北针和真太阳时。
- 修复一百二十分金甲子生成：每一山的五个分金现在保持同一地支组合，不再把连续六十甲子错误地跨山混排；同时补齐六十四卦上下卦名称和六位二进制字段。
- 修复繁体中文八宅宅卦、二十四山、六十四卦以及天机长卷正文的简繁混用；长卷的简体中文段落也不再显示繁体字。
- 三合十二长生改按坐山所属四大局（申子辰水、亥卯未木、寅午戌火、巳酉丑金）和目标山地支计算，不再使用无业务含义的数组下标偏移。
- StoreKit 本地交易幂等记录不再只保留最近 100 条，防止旧交易回放时因记录被淘汰而重复发放消耗型额度。
- 修复奇门八门排布的时辰索引，按 23:00 起算的子丑寅卯等十二时辰计算，避免整点边界错一支。
- 择日和真太阳时四柱在 23:00 子初切换日柱，并使用当前日历处理夏令时跨日，避免传统日柱与民用日期错位。
- 修复紫白流月按公历年份余数误判年支的问题，改用甲子纪年索引；2024 甲辰、2025 乙巳等年份现在进入正确的五虎遁分组。
- 修复罗盘节气环英文仍显示中文卦名首字、繁体仍显示简体节气字的问题，节气和对应消息卦现在按当前语言显示。
- 修复 StoreKit 恢复已处理过的会员交易时直接跳过权益同步的问题；恢复现在会重新应用非消耗型权益，同时保持订阅恢复幂等，不会重复延长周期。
- 修复罗盘刷新节流在 359°/0°边界把小幅转动误判为 360°大跳变；现在使用环形角度差计算。
- 修复奇门九宫排布因中宫占用数组索引而跳过一门、重复另一门的问题；八门、九神和天干现在按八个非中宫顺序独立推进。
- 修复 AR 在拍照并发、切换镜头、切后台时丢失照片回调导致 AI 扫描无限转圈的问题；取消中的拍摄会回传失败结果并清理扫描状态。
- 修复紫白流月在大雪前被公历 12 月强制归入 12 月流月的问题，流月现在完全按太阳黄经节气桶切换。
- 修复三合十二长生对艮、巽、坤、乾四个卦山的地支归属，分别按寅、巳、申、亥参与四大局判断。
- 进一步修正三合双山五行归局：按项目规则将艮丙辛归火局、坤壬乙归水局、巽庚癸归金局、乾甲丁归木局，避免乙辛癸丁按邻近地支误入其他局。
- 修复真太阳时跨越节气边界时四柱仍沿用修正前节气桶的问题；四柱年、月柱现在按经度校正后的真太阳时重新取节气。
- 修复 Vision 形煞扫描在没有检测到任何几何区域时强行返回“火形煞”的误诊；无证据帧现在明确提示重新取景。
- 奇门局数由原先的公历月日取模简化公式改为按太阳黄经节气和拆补上、中、下元五日段查表，标题同步显示实际元段。
- StoreKit 处于 Ask to Buy/组织审批的 deferred 状态时会释放购买中锁定并提示待批准，后续交易更新仍可正常完成；跨设备恢复年度会员时按恢复交易重建未过期周期，不会重复叠加年度时长；旧版只有 VIP 布尔标记的安装会迁移为一个明确的 365 天过渡期。
- 紫白流月的页面月份标题继续保持一月的公历显示习惯，但客星入中改用传统节气月（寅月为正月）计算，修复立春后客星整体错一月的问题。
- 户型立极点所在房间现在归入中宫，中央卫生间等布局可以触发中宫诊断；Vision 会过滤面积过小的矩形噪声，并将失败信息统一本地化。
- 罗盘磁针和真北针改为在固定屏幕坐标系中跟随有效磁航向绘制，真北按东偏为正的方向校正；`CompassHeadingState.trueHeading` 也会同步当前地理真北值。
- 天机长卷 Photos 保存失败且权限被拒绝时提供系统设置入口；导出状态和相册回调保持在主线程，避免重复点击或后台回调造成额度状态错乱。
- 奇门最佳动身方现在结合设备当前航向给出左右转向角度；原先传入的 `heading` 参数未参与导航结果，用户只能看到绝对方位。
- 应用系统名称、会员页、AR 水印和天机长卷落款统一为“天机演象 / 天機演象 / TianJi YanXiang”，避免系统名称与导出内容显示旧品牌。
- 紫白九宫现在使用实时罗盘向首标记当前对应宫位；同时修正二五交加误报，并将流月五黄纳入危险提示。
- 奇门中宫不再伪装成吉门，改为中性太极宫，避免出行导航将无门的中宫显示为绿色吉位。

## 发布前仍需完成

- 在 App Store Connect 创建四个商品并确认 Bundle ID、价格、订阅组和审核元数据；StoreKit 1 的本地权益适合离线体验，生产环境仍应以 Apple receipt/StoreKit 2 服务端校验为最终权益来源。
- 用真机验证磁场干扰、定位拒绝、相机切换、Photos 拒绝、订阅续期/恢复和 StoreKit 沙盒交易；当前容器没有 Xcode/iOS SDK，无法在此处执行 `xcodebuild`。
- Vision 当前是几何候选识别器，不等同于经过训练的建筑/道路分类模型；若需要生产级语义识别，应提供并审核一个 Core ML 模型，再替换分类层。
- iOS 真机编译和 StoreKit 沙盒验证仍需在 macOS/Xcode 环境执行；本容器只能完成静态语法、兼容性、资源和工程配置检查。
