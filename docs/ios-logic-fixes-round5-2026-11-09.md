# iOS 第五轮逻辑问题修复

对应[第五轮检查](ios-logic-review-round5-2026-11-09.md)的8项问题，均已实现修复。

## 报告与页面统一

- 住宅向首不再依赖当前展示的功能。九星每次刷新时生成完整 `TianJiAnalysisSnapshot`，冻结向首、日期、元运、下卦/替卦、房屋标识、空间上下文及附件。返回菜单导出采用最后实际查看的分析快照，换房时失效。
- 罗盘报告显式捕获空住宅附件，避免把当前住宅资料混进临时罗盘分析；住宅报告按同一户型、坐标、日期重新生成附带体检内容。
- 长卷复用 `XuanKongDeepAnalyzer` 的方位用途和全部行动；移除旧的催财、健康、布局拼接。综合说明改用当前格局解释，逐宫及年月章节使用综合用途和对应星数组合来源，避免后续段落再次给出相反建议。
- 对2026-11-09、九运、丙山壬向、下卦增加回归用例，要求南宫年星5覆盖本命向星9的活动建议。
- 房间名称及动态依据可能增加报告长度，改为先在1像素画布测量完整内容，再分配实际长图高度，避免固定15000像素截断尾部。

## 立极点与空间数据

- RoomPlan同步时保存源测绘ID及世界X/Z到归一户型的映射，保留真实包络、跨度和留白比例。映射随户型保存、载入和宅谱备份保留；替换图片、重置户型时清除。
- 实测门窗、床灶先映射到图纸坐标，再与房间统一使用当前立极点、长宽比、中宫范围和坐标基准归宫。
- 3D查看器仅修正房间用途时保留源测绘ID，不使仍有效的坐标映射失效。
- 无映射或测绘ID不匹配时不合并点对象，显示重新同步提示；旧户型依然能查看房间规则。

## 测绘、房屋与PK

- 存储明确区分实测、虚拟和图纸推演来源。无实测档案时，连续VR保存更新活动模型及组合存档；有实测档案时保留其优先级。
- RoomPlan同房导入改走 `refreshMeasuredSurvey`，保留现场观察、外部记录及房屋身份；陈旧采集仍由原有 `propertyID` 拒绝。
- 新增跨启动稳定的 `propertyKey`，与拒绝旧写入的会话 `propertyID` 分离。宅谱保存/载入保留稳定标识，旧档案首次载入采用其档案ID。旧组合存档自动补齐来源和稳定标识。
- 房源PK拆开图纸方向与住宅向首：归宫使用坐标基准，坐向标签、人宅配对及其分数使用实际向首，兼容无显式向首的旧资料。

## 提醒与CI

- 吉日候选ID包含完整公历日期；提醒进一步以稳定房屋标识、规范坐山名和年月日生成独立ID，查询、预约、取消使用同一键。打开择日工具时冻结提醒上下文。
- 原有无住宅元数据的通知迁入未关联列表，保留原通知；可单独取消，不能因另一套房同日操作而删除。启动择日工具、回前台及每分钟刷新时清理已触发/移除的预约状态。
- 预约防重入；异步预约与待处理通知列表核对使用代次校验，避免较早查询覆盖新预约。
- CI测试步骤限时30分钟，任务总额度45分钟。3次上传各3分钟及15/30秒等待后仍保留超过5分钟余量，维持测试失败与上传失败分开处理。
